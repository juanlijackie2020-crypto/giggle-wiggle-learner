## 1. 产品目标与设计原则

让孩子先因为探索、收集、跑酷、解谜而想玩，再通过数学（主要）和少量语文题获得游戏奖励。完整循环：角色换装 → 进入地图 → 探索/任务/躲避怪物 → 解题 → 开宝箱 → 获得材料 → 建造/解锁下一关。

- 游戏优先：题目嵌入机关、宝箱，不把整张地图变成练习册。
- 学习有效：题目可重试，提供逐级提示；记录独立答对和提示后答对，不以惩罚促学习。
- 适龄安全：怪物为卡通风格，无血腥；失败回到检查点，不能永久失去奖励。
- 真实3D：角色和摄像机可移动、场景可探索、地形有碰撞；概念插画不能代替可玩的3D原型。
- 美术原创：采用原创体素角色、纹理、名称和场景；不得直接复制Minecraft官方素材。

## 2. 用户与核心体验

玩家：骞骞。辅助用户：家长。玩家首次进入角色装扮室，自定义方块小人的肤色、衣服颜色、服装款式；自动存档，关卡内一致显示。第三人称镜头；电脑支持WASD、空格、E、鼠标旋转；手机支持屏幕方向键、跳跃、互动与触控镜头。大字体中文UI、背包、可选任务板、任务追踪、检查点、音量开关。V3.1 扩展装扮、随机计算题和主角与动物的有声对话，详细规则见第 9–14 节。

失败与重试：跌落、碰到怪物或触发陷阱只重置当前挑战段；不清空已经领取的永久奖励。支持随时暂停与重新开始关卡。

## 9. 随机计算题与难度升级

### 9.1 难度与出题规则

建议默认采用以下难度档，由家长在家长视图选择；孩子答错不自动升级，也不扣奖励。当前题组开始后锁定难度，设置变更在下一轮生效。

| 难度档 | 建议范围 | 用途 |
| --- | --- | --- |
| 热身 | 0–10 整数加减法 | 需要帮助时可由家长选择 |
| 标准（默认） | 0–20 整数加减法，包含进位与退位 | 相比 V3.0 提高难度 |
| 挑战 | 0–50 整数加减法，包含两位数运算 | 家长主动选择，非强制通关条件 |

- 每轮恰好 3 题，至少 1 道加法、1 道减法；标准/挑战档至少包含 1 道进位或退位题。例：8+7、16−9、6+8，仅为题型示例，不是固定题库。
- 两个操作数、正确答案与选项都在当前档的整数范围内；减法不得产生负数。第一关不引入乘除、分数、计时抢答。
- 每题 4 个互不重复的选项，且恰好 1 个正确；正确选项位置随机。错误选项合理，例如相邻数或常见计数错误，不使用重复值或超出范围的值凑数。
- 同组题干不得重复；加法交换顺序视为同一道题，如 8+7 与 7+8 不得同时出现。下一轮 3 题均避开紧邻上一轮的题干，不能只换顺序或换选项冒充新题。
- “每次不一样”指每次新开一轮挑战，不承诺有限题域内永远不重复。生成器采用有限候选集筛选/有界重试，候选不足时给出配置错误并允许重试，不无限循环或静默退回旧题组。
- 运算规则、范围、题量、提示模板以独立 JSON 配置管理；生成器负责计算和校验答案，不依赖后端或付费 API。

### 9.2 生成时机与连续学习

- 进入第一关新一轮时生成并保存题组；题目仍在材料齐全、到达宝箱后展示，不提前向儿童公开答案。
- 明确点击“重新开始关卡”后创建新题组，同时按原规则重置本轮收集。若以后增加独立练习入口，也必须显式开始新一轮，且不重复发关卡奖励。
- 关闭/重新打开题目、答错重试、怪物碰撞回检查点、暂停或刷新都保留同一组题、选项顺序、已答对进度和提示状态。刷新不能用来换题。
- 首次答错给适配当前算式的短提示；第二次答错展示分组点数、十格框或拆十图解。提示由本题操作数生成，不能继续沿用固定题的图解。
- 不在儿童答题页面预先显示参考答案。家长视图按题目实例显示算式、参考答案、难度、尝试次数、提示次数、是否首次独立答对和完成时间。
- 收集 3 木头、5 琥珀且答对本轮全部 3 题才能开箱。奖励仍为木头方块 ×10，唯一奖励 ID 不随随机种子、题组或重玩次数变化。

## 10. 任务选择与玩法类型扩展

“任务选择”指可选择的冒险活动类别。主线与可选活动分开，避免孩子以为必须做完所有支线才能开宝箱。

| 类型 | 第一关建议内容 | 完成条件 | 本轮范围 |
| --- | --- | --- | --- |
| 主线收集与宝箱 | 3 木头、5 琥珀、3 道随机计算题 | 材料齐全并开箱 | 保留并升级 |
| 动物寻踪 | 找到兔子和松鼠，选择问候或询问线索 | 完成两次指定动物的对话互动 | 新增 |
| 森林探索 | 探访树屋入口、桥边安全点、琥珀林 | 到达 3 个指定地点并互动确认 | 新增 |
| 轻量跑酷 | 跨过低矮木桩，抵达标记旗 | 按顺序经过路线标记 | 新增 |
| 观察与规律 | 找出颜色或形状规律 | 完成独立小机关 | 后续候选，不计本轮验收 |

上述新增任务及数量为建议默认，每项约 3–5 分钟；保留自由探索，可选任务无强制倒计时、不增加战斗。跑酷失败回该任务起点，保留主线收集和永久奖励。

任务板要求：

- 用图标、名称、简短目标和进度显示任务类型，明确标注“主线 / 可选”。支持接受、切换、继续、放弃；切换不丢已完成步骤，放弃前说明本轮步骤会重置。
- 建议同时追踪 1 条主线和 1 条可选任务；未选中的任务不会挤满 HUD。任务入口在电脑与手机均可点击。
- 每个地点、动物、任务步骤都有稳定 ID；重复触发同一步不得重复计数。已采集物不会让后来接取的任务无法完成，可读取已有进度或使用独立目标物。
- 可选任务不改变主线宝箱的开启条件，不额外消耗那 3 木头和 5 琥珀；任务窗口、对话窗口打开时暂停危险，关闭后恢复控制。
- 建议可选任务先奖励一次性完成徽章，不新增可消费资源。若后续增加宝石或材料奖励，需另定数量、用途与唯一领取 ID；本版不自动修改宝石经济或开放无限刷取。

## 11. 角色服饰与配色扩展

保留肤色选择、第三人称角色和自动存档。建议默认由现有 5 种衣色 / 3 种款式扩展为至少 8 种衣色 / 6 种服饰。

| 维度 | 建议默认内容 | 验收要求 |
| --- | --- | --- |
| 衣服主色 | 天空蓝、森林绿、琥珀黄、珊瑚红、葡萄紫、湖水青、樱花粉、奶油白 | 至少 8 种可辨识色块，有名称与选中标记 |
| 服饰款式 | 保留探险家、卫衣、森林游侠；新增雨衣、小动物连帽装、工匠背带装 | 至少 6 种，轮廓/帽子/口袋等可见差异，不能只改名称 |
| 成套配色 | 每套包含协调的衣服、裤子和配饰颜色 | 建议提供至少 6 套一键搭配，仍允许单独换衣色 |
| 肤色 | 保留现有选择，与服饰独立 | 换装不能重置肤色 |

装扮室用明亮的林间背景、较大的可旋转 3D 人物、色块和款式卡片；点击即可预览，保存后地图人物一致。款式差异使用原创几何体，不通过增加大量材质或透明层拖慢手机。

UAT 版建议所有基础款直接可选，不引入付费或抽取。外观不改变速度、跳跃、判题或奖励。配饰解锁规则可后续讨论，不阻塞换装模块。刷新、重开关卡、升级旧存档后保留合法外观；已下架款式提供稳定默认回退。

## 12. 色彩、美术与 UI 升级

### 12.1 附件的可执行视觉方向

本次六关图的核心特征是明亮饱满的色彩、丰富的森林层次、发光宝物、木质标题与醒目的奖励符号。第一关优先落实这些特征；其余五关的配色只作未来风格参考。不要把整张海报当作 3D 游戏画面或将六格海报铺满游戏 HUD。

| 部位 | 第一关设计要求 |
| --- | --- |
| 森林与天空 | 多层翠绿/嫩绿树冠、蓝天、温暖日光；避免全场同一种灰绿或偏暗背景 |
| 琥珀与目标 | 金黄/橙色发光琥珀，靠近可交互物时出现清楚的轮廓或图标；弱性能设备保留亮色提示 |
| 场景层次 | 前景花草、中景动物与路径、远景树屋/高树，河流清楚可辨；装饰不遮挡可行走路线 |
| 主角 | 鲜明服色与树林形成对比，人物轮廓在移动中可辨认 |
| 面板 | 木牌标题、暖色纸张底、清晰图标，少量体素描边与层次，正文不直接压在复杂纹理上 |
| 奖励反馈 | 宝箱开盖、宝物光点、木头方块入包动画；背包准确展示实际道具，不用宝石图标冒充木头奖励 |

建议初始色板：森林绿 `#2E8B46`、嫩叶绿 `#8BCF4A`、天空蓝 `#65C7F7`、琥珀金 `#FFC247`、木色 `#80502D`、纸张色 `#FFF3D6`、正文深棕 `#30281F`。这些是视觉提案；按钮和文字组合需单独检验可读性，不能因为色值在色板内就默认对比度合格。

附件中的成熟游戏角色、武器与标识不作为可复制素材；保持原创体素造型，画面出现武器不构成本轮新增攻击系统的授权。巨量装饰通过实例化、分区与距离裁减实现，不能用堆叠对象换取截图效果。

### 12.2 页面与操作要求

- 开始页：醒目的中文名称、真实森林预览或同风格背景、大尺寸“开始 / 继续冒险”，清楚的加载状态、失败原因与重试入口。
- 游戏页：顶部精简目标与资源，主视区留给森林；任务板、装扮、背包、暂停入口易找。手机底部摇杆、跳跃、互动不与任务按钮重叠，并避开刘海和底部安全区。
- 任务板：每类任务有可辨识图标、短目标和进度；完成与未完成不仅靠颜色区分。
- 答题页：大算式、4 个大选项、可展开提示、进度“第 1/3 题”；装饰不遮挡数字。错误反馈温和，正确反馈短促明确。
- 对话页：主角/动物头像、当前说话者、字幕、回应卡片、重播和关闭；孩子能看出谁在说话。
- 装扮与背包：统一卡片与按钮风格，展示真实 3D 外观和明确物品数量，空状态也给简单说明。
- 建议儿童主要文字不小于 18 CSS px，触控区域至少 48×48 CSS px；正文对比度至少 4.5:1，大字至少 3:1。窄屏、横屏与竖屏均不得出现不可操作的裁切。
- 尊重减少动态效果设置，避免快速闪烁；提供低画质模式，降低阴影、粒子和远处装饰，保留目标标识与色彩层次。

性能沿用对象池/实例化、设备像素比上限与怪物限流。建议目标为选定中档测试手机通常达到 30 FPS；验收记录机型、浏览器、分辨率和场景实测值，不将目标写成已通过。音频与美术加载不能重新造成只有 HUD 的黑屏。

## 13. 动物声音与主角有声对话

### 13.1 交互闭环

本版建议采用预设分支对白：孩子通过文字/图片回应卡选择内容，由主角说出，再由动物回复。无需麦克风、语音识别、账号或在线 AI；开放式语音聊天作为另行定义的后续能力。

1. 靠近动物，显示名称和“交流”；按 E 或手机互动按钮发起。
2. 动物播放适合该物种的轻柔招呼声/动作，打开对话框并暂停周围危险。
3. 主角播放有内容的问候语，字幕同步显示；孩子选择“打招呼”或“询问线索”等回应。
4. 被选回应由主角配音说出，动物用有声角色对白回答；线索与当前任务进度一致，不指向已消失的目标。
5. 支持重播当前句、跳过与结束对话；关闭后立即恢复游戏操作，无卡住或遗留按键。

建议兔子示例：主角“你好，小兔子！” → 兔子“你好，探险家！” → 孩子选择“琥珀在哪里？” → 主角说出问题 → 兔子“沿着河边找找，发金光的就是琥珀。”这是可评审的对白示例，最终文字需与地图实际位置核对。

### 13.2 声音内容与体验

- 第一关兔子、长尾鹿、松鼠、小鸟、狐狸、刺猬六类动物均有互动声音；同类动物可复用素材。每类建议至少一段问候与一段有内容的回应，不能仅用“叮”一声替代对话。
- 主角至少具备问候、询问线索和感谢三类实际台词；动物回复也可听懂。默认中文，语气温暖、语速适合儿童、句子短，建议每句 2–6 秒。
- 动物自然叫声和拟人对白分别管理；个别真实动物叫声不适合儿童时使用原创温和拟音，避免刺耳与惊吓。
- 全部对白配字幕和说话者标识。静音或听不到声音时仍能完成任务；低识字量儿童可借助头像、图标和重播操作。
- 建议使用随静态站点发布的原创/已授权配音文件作为可靠音源，记录来源与授权。浏览器 TTS 只能作为可选补充，不能依赖系统恰好安装某个语音包才能听到对白。
- 提供总静音、对白音量、音效音量与试听，保存设置；背景音乐可后续添加，不是本轮必要条件。

### 13.3 浏览器与音频可靠性

- 在用户点击“开始”或明确互动后解锁音频；加载期间不自动出声。适配 Safari 自动播放限制，播放失败显示“点此重试声音”，保留字幕与继续游戏能力。
- 同时最多 1 路对白；快速切换动物先取消上一段语音及队列，防止重叠。对白播放时降低环境音/提示音，不能盖住台词。
- 暂停、切换后台、关闭对话或重开关卡时停止当前对白；返回后由孩子重播，不突然播放过期对白。点静音应立即停止声音，取消静音不重播已取消内容。
- 对白资源按需加载、缓存复用；音频缺失或超时不阻塞 3D 场景、任务计数或对话关闭，提供重试与字幕降级。
- 资源路径兼容 GitHub Pages 仓库子目录和 Netlify 根目录；支持的音频格式须在真实 iPhone Safari HTTPS 环境验证，不用桌面浏览器模拟替代。

## 14. 数据配置、存档与兼容

建议在现有 JSON 配置与 localStorage 存档上扩展，不要求后端：

| 数据 | 需要保存或配置的内容 |
| --- | --- |
| 题组 QuestionSet | setId、runId、seed、generatorVersion、difficulty、3 个完整题目快照及选项顺序、上一轮题干指纹 |
| 题目学习记录 | 独立 questionInstanceId、题型、算式、attemptCount、hintCount、firstTryCorrect、completedAt；不能用固定的 3 个 ID 覆盖不同算式历史 |
| 任务 TaskDefinition | taskId、类型、是否主线、步骤目标 ID、前置条件、完成标记、奖励领取 ID |
| 装扮 PlayerAppearance | 稳定的 skinId、outfitId、colorId/paletteId；保留旧款映射 |
| 对白 DialogueDefinition | dialogueId、speakerId、文本、回应分支、触发条件、audioAssetId；音频清单包含路径、语言与授权说明 |
| 声音 AudioPreferences | muted、voiceVolume、effectsVolume；暂停中断状态不当作待播放队列持久化 |
| SaveGame | schemaVersion、当前题组/任务步骤、背包、装扮、检查点、永久通关、唯一奖励领取记录 |

存档迁移必须保留已有 10 木头奖励、外观、通关和学习记录；旧固定题学习记录标为历史版本，不伪装成随机题记录。建议迁移时允许正在进行的旧固定题组完成一次，明确重开后使用随机题，避免中途清空已答对进度。

题目生成完成即存储，刷新读取快照，不凭种子重新生成后悄悄改变选项。历史题组摘要建议按最近 100 组保留，并保留累计统计；不截断当前题组、永久奖励 ID 或任务奖励领取记录。存储失败须提示“本次进度可能无法保存”，不能显示虚假的保存成功。

“重新开始”重置本轮目标和当前题组，保留永久奖励与外观。每个任务的奖励与主线奖励均有稳定 ID，不能因新题组、新装扮、新版本或重新开始而重新发放。

## 15. 分模块开发与 UAT 验收

UAT 是家长和骞骞实际试玩、确认是否好用好玩的用户验收。可先验收一个模块，不需要先合并 PR 或完成其他五关。使用测试分支的 HTTPS 预览站点；通过一个模块后继续下一项，最终再做完整通关回归。

建议顺序：视觉与装扮 → 动物有声对话 → 随机计算题 → 任务板与存档闭环。模块 UAT 可以在独立测试场景进行，最终必须回到实际 3D 第一关整体验收。

| 模块 | 家长与孩子的操作 | 通过标准 |
| --- | --- | --- |
| A：视觉与装扮（先做） | 对照附件观察森林，选择 3 套不同服饰与配色，进入游戏并刷新；手机横竖屏各试一次 | 至少 8 色/6 款可选、3D 外观有区别且保存；主角和琥珀清晰，字和按钮可读可点；家长/骞骞确认更有吸引力 |
| B：有声对话 | 与六类动物交流；选择问候和问线索；重播、静音、切后台再返回 | 主角和动物均有清楚台词；字幕匹配；无重叠/过期播放；静音仍能完成互动 |
| C：随机题 | 连续新开 10 轮，检查每轮 3 题；答错、关闭、刷新；完成 1 轮 | 相邻轮题干不重复、每题 4 个不同选项且 1 个正确；范围/进退位符合设置；刷新不换题，提示符合当前算式 |
| D：任务与进度 | 切换三类新增任务、回检查点、暂停、刷新；完成主线并重玩 | 目标清楚、步骤不重复计数；支线不阻塞宝箱；每个奖励只发一次，刷新与重玩保留永久奖励 |
| E：整体验收 | 从换装、自由探索、动物对话、收集、答题一直玩到开箱 | 形成可玩的完整闭环；声音与动画不阻塞输入，移动端不黑屏、无严重报错 |

自动化测试计划（待实现，不是本次执行结果）：

- 生成器：固定种子可复现；批量种子检查题量、范围、两种运算、进退位约束、同组及跨相邻组去重、选项唯一与准确判分；候选不足可控失败。
- 状态与迁移：刷新保持题组和选项，重开换题，保留旧版奖励与学习记录；重复互动/重复开箱/动画中刷新不重复发奖；切换支线与旧收集物不会造成死锁。
- 浏览器流程：实际操作换装、三类新增任务、两方对白、错题提示、宝箱奖励与静音；模拟音频缺失、播放拒绝、存储失败以及页面失焦。
- 视觉与移动端：不同窗口尺寸、旋转、触屏按钮、WebGL 初始化失败提示、上下文恢复和 Pages 子路径资源加载。
- 声音“实际可听见”、主观美术吸引力、真实手机帧率、发热与 Safari 音频解锁必须人工验证，不能仅靠音频 API mock 或截图判定。

UAT 记录模板：版本/提交号、HTTPS 地址、设备/系统/浏览器、模块、操作步骤、预期、实际结果、截图或录屏、通过/待修复/未验证、验收人和日期。没有真实设备或无法执行的步骤一律标为“未验证”。

## 16. V3.1 第一关历史设计建议与待定项

本节保留第一关原始设计过程中的建议，当前第一关已收到用户 UAT 通过反馈。后五关只提交设计审阅，不按本节自动制作原型或开始开发；后五关以第 18 节和 V3.3 专项设计稿为准：

- 标准难度暂建议 20 以内、挑战 50 以内；最终上限与进退位比例结合骞骞的试玩表现确定，不把增加难度等同于强制超龄题。
- 三类新增可选任务、至少 8 色/6 款及其名称为本轮建议范围；服饰美术、声音角色和具体对白需在模块 UAT 中确认。

## 17. V3.2 · 扩展森林、精细体素模型与实体装备

来源：2026-11-06 用户四项要求及动物、村庄、自然、动作和河畔森林参考图。只升级第一关；海洋等图示用于整体视觉参考，不扩展其余五关。以原创程序几何体重建层次、配色和轮廓，不导入图片中的官方模型、标志或纹理。

### 17.1 扩大可探索范围

- 从 44 × 52 扩大至 80 × 84 世界单位，可活动平面面积约原版 2.94 倍。
- 原主线木头、琥珀、宝箱与检查点位置保留；新增花甸、白桦林、河畔小屋、山径低台阶。第二座桥有真实桥面和栏杆碰撞，小屋有可进入的门洞。
- 地面、河流、物理边界和小地图使用一致范围；标出四处新增石英矿点，给扩展区域提供探索目标。
- 山峰为远景；可走区域以实体边界为准。河流仍采用回检查点规则，不新增游泳机制。

### 17.2 怪物、人物与动物美术

- 绿色四足怪采用亮绿、深绿和黄绿像素斑块，不再使用原来的青灰配色。保持原创细节、卡通风格和躲避玩法。
- 人物增加层次头发、眼睛高光、眉毛、鼻子、衣领、缝线、鞋底；保留六种服装与全部配色。镐在手中，背包固定于人物背部，肩带、扣带、侧袋可见。
- 兔子、鹿、松鼠、狐狸、鸟、刺猬分别建立独立模型；长耳/耳内、鹿角/斑点/蹄子、卷尾、白尾尖、鸟喙/翅膀、刺背等物种特征清晰。
- 树叶增加原创像素斑块，扩展区增加白桦树干、十字花瓣、河岸沙边、石径和山景。静态细节合并，树与怪物细节实例化，怪物仍最多 24 只。

### 17.3 工具镐与真实背包

- 默认发给玩家一把青晶工具镐和探险背包；旧存档自动补齐这两件基础装备。
- 镐可装备/收起，电脑 F 或屏幕「挥镐」触发手臂挥动。近距离 E/点击矿物也可采矿；只有装备镐才可采集琥珀和新增石英，不攻击动物或怪物。
- 一次有效互动收集一块矿物，数量更新与挥镐同时反馈。石英四处各领一次，存档并跨重玩保留；属于收藏，不额外阻塞主线或兑换奖励。
- 背包提供 12 个物品格、真实道具图标、数量、详情、工具装备状态和可旋转人物装备预览。B / 背包按钮可打开。
- 背包外观可以收起；隐藏外观不删除道具或收集进度。任务木头/琥珀仍随本轮重开重置，永久木头方块 ×10、石英和徽章保留。
- 所有数量来自同一存档状态，不另建展示专用虚假数量。不加入容量不足、掉落物丢失或耐久损坏惩罚。

### 17.4 验收

1. 玩家能实际走到旧地图范围外，在新增矿点采矿，通过第二座桥并进入小屋；小地图不越界。
2. 拖动人物预览可看到镐和背包；六种动物轮廓不同；绿色怪物配色对照用户图片验收。
3. 收起镐时采矿被阻止；重新装备恢复；重复矿点互动不增发数量；刷新和重玩保存永久矿物及装备。
4. 手机横竖屏能点击挥镐、背包与装备按钮，原摇杆/跳跃/互动仍可用。
5. 原主线收集、随机数学题、宝箱一次性奖励仍能完成。
6. 工程测试与人工美术 UAT 分开；iPhone Safari 真机、长期性能与孩子主观视觉认可，未实测不得标为通过。
